# Архитектура

Кортекс: мост контекста (Context Bridge). Нативная программа Windows на C++ и Win32.

Авторство: **ProtocolTeam (Zhandos), 6 ноября 2026 года**. Условия — в [LICENSE](../LICENSE): просмотр разрешён; копирование, изменение, коммерческое использование и распространение без письменного разрешения ProtocolTeam (Zhandos) запрещены.

Память живёт снаружи модели. Модель — заменяемый HTTP-вызов. Пирамида, файлы и протокол указателя принадлежат программе.

## Состав

| Файл | Роль |
| --- | --- |
| `src/bridge.cpp` | Окно, сжатие, указатель, чтение файла, поиск, локальный ответ |
| `src/json.hpp` | Разбор ответов модели |
| `src/http.cpp` | POST через WinHTTP |
| `src/gui.cpp` | Окно Win32: адаптер, ключ, диалог, список файлов |
| `tests/bridge_test.cpp` | Переполнение, файл, указатель, повторное чтение |

Сборка: CMake. Исполняемый файл — `context-bridge.exe`, подсистема Windows GUI. GitHub Actions собирает его компилятором Visual Studio в конфигурации Release со статической CRT, чтобы рядом не нужен был отдельный установщик runtime.

## Слои

| Слой | Что хранит |
| --- | --- |
| L1, окно | То, что уходит в текущий запрос: протокол, указатели, живой диалог |
| L2, конспекты | Короткая фраза вместо сброшенного куска, внутри того же окна |
| L3, файлы | Полный оригинал куска под номером, каталог `memory/segments` |

Реплика — роль и текст. Роли: system, user, assistant, tool. Пометки «закреплено», «указатель», номер файла в JSON запроса не входят. Модель видит только текст указателя.

## Бюджет

- размер окна задаётся в поле программы, по умолчанию 4096;
- запас под ответ — 512, но не больше пятой части окна, если окно меньше запаса;
- порог — доля бюджета промпта, по умолчанию 0,75.

Оценка токенов: байт ASCII даёт одну единицу, прочий байт — две, сумма делится на четыре, плюс четыре единицы на реплику. Это не словарь конкретной модели. Смена адаптера не меняет оценку: своего токенизатора у HTTP-адаптеров в этой программе нет.

Сжатие запускается, когда оценка горячего списка достигает порога.

## Сжатие

Пока окно выше порога и есть что сбрасывать:

1. Список делится на закреплённое начало, сбрасываемую голову и хвост из последних реплик (`min_keep_messages`, по умолчанию 4).
2. Если головы нет, а окно всё ещё не влезает, в голову уходит весь хвост, кроме самой новой реплики.
3. Из головы берётся кусок: не больше 8 реплик и не больше 45% бюджета, либо явного предела. Первая реплика берётся всегда.
4. Фраза куска собирается по частым словам. Если запись файла не удалась, окно не меняется.
5. Сначала оригинал пишется во временный файл и заменяет номер. Только потом кусок в окне заменяется строкой.

Строка:

```text
file <номер>: <фраза>; details and original text are in the file
```

Файл бывает диалогом или оглавлением. Оглавление — если кусок состоял только из указателей. Оригиналы не переписываются.

Кнопка «Сжать» забирает один кусок даже ниже порога.

Формат файла — длинами блоков, не строками текста, чтобы перевод строки внутри реплики не ломал чтение. Номер — только цифры, чтобы в путь нельзя было подставить выход из каталога.

## Один ход

1. Реплика пользователя добавляется в окно.
2. Окно поджимается под порог.
3. Выбранный адаптер получает JSON и отвечает.
4. Если в ответе есть вызов `read_context_file` / `search_context` или токен `[[ctx:read:]]` / `[[ctx:search:]]`, чтение выполняется во временной копии запроса. Модель зовётся снова, не больше трёх раз.
5. Токены вырезаются из видимого ответа. Ответ дописывается в сессию.
6. Окно поджимается ещё раз и пишется в `memory/session.txt`.

Временная копия после хода выбрасывается. Следующий ход видит указатель, а не оригинал, пока модель не попросит снова.

Неизвестный номер становится текстом ошибки внутри запроса к модели.

## Адаптеры

Общая работа одна: из канонических реплик собрать тело запроса и разобрать ответ.

| Вид | Запрос |
| --- | --- |
| Локальный | Сети нет. Ответ цитирует только то, что уже лежит в переданных репликах. Просьба перечитать файл с номером порождает `[[ctx:read:N]]`, второй шаг цитирует оригинал. |
| OpenAI, llama.cpp, Hugging Face | `POST …/v1/chat/completions`. Если в адресе нет суффикса `/v1`, он добавляется. Инструменты уходят в поле `tools`. |
| Ollama | `POST …/api/chat`, `stream: false`. Суффикс `/v1` с адреса снимается. |

Ключ, если он не пустой, уходит заголовком `Authorization: Bearer`. В файлы сегментов он не пишется. Он попадает только в `memory/settings.txt`.

Ошибка HTTP или поле `error` в JSON показывается в строке состояния. Реплика пользователя при этом остаётся в окне.

## Поиск

Запрос режется на слова. Совпадение с конспектом и телом увеличивает счёт. Запрос из цифр, равный номеру, возвращает этот файл сразу. Читается каждый сегмент. Для одного локального архива этого достаточно.

## Поток окна

Сеть вызывается в отдельном потоке, чтобы окно Win32 не замирало. Пока запрос идёт, кнопки отправки, применения и сжатия выключены. Результат возвращается сообщением окна, и только тогда список файлов и лента перерисовываются. Лента собирается заново из канонических реплик: протокол скрыт, указатель показан отдельным блоком.

## Чего программа не делает

Потокового ответа, нескольких пользователей, шифрования, векторного поиска, локальных весов Hugging Face и дообучения. Мост — политика контекста, не вторая модель.
